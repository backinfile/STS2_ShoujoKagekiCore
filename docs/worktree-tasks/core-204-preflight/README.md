## 用户原始输入

> 提升core版本号，进行karen发布前完整测试

## 计划

1. 将 Core 发行号从 2.0.3 升至 2.0.4，构建完整 Core 和配套 Karen v1.0.3 候选。
2. 用候选包完成桌面四套版本的单人、同版联机、存档和发布产物验证，复核新增闪耀报错。
3. 记录实际通过项、阻塞和包哈希。原检出的巡检改动留在原检出。
## 变更与候选包

- 更新 Core 发行清单、构建默认版本和发行文档至 2.0.4。Karen 维持 v1.0.3，最低 Core 依赖为 2.0.3，本次候选内嵌 Core 2.0.4。

## 定向结果

- v0.113.0 同时安装 Core 2.0.3 和 2.0.4。首次和重启均报告两个候选且实际加载 2.0.4。关闭 BaseLib 玩家 JSON 扩展后，闪耀耗尽档案写盘、恢复和显示均通过。
- v0.113.0 的受控异常触发四类闪耀诊断，隔离后台均通过 `/api/errors` 收到并保留相应上下文。覆盖耗尽清理异常、写盘、读档及原生复制生成空壳，正常对局没有产生诊断。后台协议 8 项和报错接口 14 项通过。
- Android 导入包校验 5 项通过。本地测试密钥签名 APK 的 v2/v3 签名、ARM64 清单及 227 个内嵌程序文件哈希通过。JVM 完整解包及 13 项安装回归通过。本轮没有连接 ARM64 真机，原生冷启动、实机覆盖安装与续玩尚待验证。
- 用相同游戏引用重新执行 2.0.3 与 2.0.4 的巡检探针，逐条结果一致。稳定版 2 项、正式版 3 项、测试版 2 项是已有失败，涉及探针对耗尽补丁的反射查找和正式版的高优先级 Prefix 短路探针。测试版旧模型隔离回归通过。
