## 原因追查

本体开战逐张复制永久牌到抽牌堆。源牌的闪耀余量小于等于 0，或已经标为耗尽时，Core 将普通复制替换为空壳。永久牌若仍留在牌组，每场战斗都会重新生成一个空壳。这条路径与附件连续两场的表现吻合。日志只记录打出了空壳，没有源牌实例或复制时的闪耀状态，无法确认原局具体在哪一步损坏了余量或牌组。[扣次和永久来源](../../../src/Modules/Shine/ShineService.cs#L184) · [复制](../../../src/Modules/Shine/ShineService.cs#L385)

- 核对 Android 启动指纹与下载的正式工坊包一致。Core 2.0.3 包含已在 1.9.8 修复的关闭父批次漏归档问题。旧修复在结算时生效，读取现存零余量永久牌时不改写牌组。附件起点是续玩，开局进程的具体包无法由这份日志核定。[旧批次修复](../fix-shine-batch-20261120/README.md)
- BaseLib 的玩家 JSON 扩展在 Android 日志里报错。Core 随后正常加载，续玩时耗尽堆为 8，终局原始记录仍有 8 张。既往同版工坊包在禁用玩家 JSON 扩展后完成两轮写盘与重启，永久牌 2/7 的预算与耗尽档案正常保留。现有证据未把 BaseLib 的异常连到这局的空壳。[存档验证](../shine-exhaust-resume/README.md)
- 第 19 层偷窃草蜢移除并归还的是原有《信封》实例。该层另获一张《水分补充》，它已经出现在耗尽档案。《迈向那个舞台》仍在两场战斗中正常打出。《出场》是尚待核对的永久来源候选。第 23 层取得的这张牌一直留到终局，两场日志均未出现它的出牌记录，原始余量未上传。
