### 遥测后台

1. **P1 · 巡检和交互请求会耗尽同一组槽位。** 接收端共八个槽位，满载时关闭 TCP 连接，Nginx 因未收到上游响应头返回 502。读取端的 Nginx 规则按到达速率限流，并发慢查询仍能占满槽位，上传和健康检查也共用这些槽位。北京时间 09:07 记录到 13 次回环上游连接重置。现网样本中，六个连接持续处理的四秒内，CPU 的 41 个调度周期全部触发配额限制。本地确认了八个槽位占满时连接被重置，释放后健康检查返回 200。先限制巡检并发，为巡检和重查询设置独立上限，保留上传与交互容量。过载返回 503 和重试提示，并记录拒绝次数。见 [请求槽位](../../../services/telemetry/app.py#L679) 和 [读取代理规则](../../../deploy/telemetry/install.py#L146)。

2. **P1 · 旧巡检每页重算筛选项，新清单仍有整轮重读条件。** 线上版本忽略 inventory=1，巡检使用每页 20 类的旧列表。20,000 类需要 1,000 页。在生产数据只读测量中，普通列表每页耗费约 0.5–0.7 秒 CPU，主要花在统计总数和筛选项，包括解析环境中的 Mod ID。当前源码的清单每页最多 500 项，按指纹继续，跳过筛选项计算。相同规模约 40 页，变化指纹的正文可以按需读取。任何被接受的新报告或计数更新都会推进全局修订号，跨页遇到变更会让巡检从头读。隔离库已复现 inventory_changed。先用生产库副本验证迁移及持续写入时的完整巡检。若反复重读，提供短期固定快照或保序增量入口。普通列表另行缓存筛选项，并保持现有响应兼容。见 [巡检口径](../../error-watch/README.md#L26)、[列表查询](../../../services/telemetry/error_reports.py#L294)、[修订号更新](../../../services/telemetry/error_reports.py#L233) 和 [清单查询](../../../services/telemetry/error_retention.py#L197)。

3. **P1 · SQLite 备份无法单独恢复原始对局下载。** 定时备份只保存 SQLite。归档将新索引写回在线库，再移除松散文件。恢复归档前的备份时，对局还在，旧索引仍指向已移除的文件，即使压缩包留在原位也找不到。隔离复现验证了在线库仍可校验原文，旧库下载失败。相同摘要的上传重试也会走既有索引的校验路径。恢复方案应让 SQLite 和原始文件对应同一恢复点，或通过归档清单校验并重建索引。演练应检查历史查询、原文 SHA256 和重复上传。见 [备份入口](../../../deploy/telemetry/install.py#L301)、[原始读取](../../../services/telemetry/app.py#L569) 和 [归档索引切换](../../../services/telemetry/app.py#L606)。

4. **P1 · 原始归档的 4 GiB 额度只增不减。** 新请求按历史累计原始字节判断。压缩会释放物理空间，记账仍保留全部原始字节。达到上限后，即使磁盘空闲，新对局也会持续收到 507。本地用一个载荷的大小作为上限，成功压缩后仍复现拒收。应先确定容量口径和原始证据保留期限，再建立冷归档或回收流程。事故时观测到的 20,000 类报错已等于默认活动类别上限，新指纹入库受该上限限制。客户端会保留 507 记录并有限重试，持续拒收会积压队列。见 [对局额度](../../../services/telemetry/app.py#L342)、[报错额度](../../../services/telemetry/error_reports.py#L213) 和 [客户端重试](../../../src/Modules/Telemetry/TelemetryUploadQueue.cs#L174)。

5. **P1 · 安装器的回退范围小于发布变更范围。** 程序链接、服务环境和 systemd 单元在 Nginx 校验前切换。失败处理恢复部分配置和程序链接，原服务环境、单元和已迁移的数据库没有纳入同一回退。备份、监控和清理定时器也在该回退块之后安装。先用副本验证迁移、新旧读取和恢复，再分开启用清理。上线校验应覆盖受保护的普通列表、清单版本和隔离库写入，当前健康检查只运行 SELECT 1。见 [切换顺序](../../../deploy/telemetry/install.py#L96)、[失败回退](../../../deploy/telemetry/install.py#L260) 和 [定时器安装](../../../deploy/telemetry/install.py#L413)。

6. **P2 · 历史统计和维护操作有第二处资源竞争。** 对局列表、角色统计及语言统计为每个响应重新汇总筛选项。全时段卡牌统计逐局解码并累加，期间持续占用处理槽和 SQLite 读取游标。归档索引发布、迁移、清理和上传争用同一个 SQLite 写入者。原始文件落盘和对局压缩还在上传写事务内。先记录按路由汇总的耗时、拒绝次数、写锁等待和容量余量，再据此缓存筛选项或预聚合重报表。指标只保留固定路由名、状态和汇总量。现有监控覆盖进程连通、磁盘、备份和归档积压。见 [对局查询](../../../services/telemetry/app.py#L444)、[上传事务](../../../services/telemetry/app.py#L355)、[清理事务](../../../services/telemetry/error_retention.py#L125) 和 [现有监控](../../../deploy/telemetry/install.py#L377)。

### 工作台后台

7. **P2 · 大请求在两层完整缓冲，并与编辑共用事件循环。** 网关收完整请求，MCP 后端再读取、拼接并解析，图片还需转 Base64。图片限额 16 MiB 在后端执行，网关沿用通用 128 MiB 上限。网关和 MCP 在同一个 Node 进程内，SQLite、散列和文件落盘包含同步步骤。按路由尽早验大小，图片采用流式转发并传递断开信号，限制并发的大包操作。非法 JSON 目前也落入通用 502 分支，应将输入错误、上游超时和连接中断分别计数和返回。实际外部包大小还受现网代理限制。本次未测量线上内存和峰值延迟。见 [网关处理](../../../tools/workbench/deploy/relay.cjs#L21)、[MCP 读取](../../../tools/workbench/mcp-daemon.cjs#L29) 和 [进程入口](../../../tools/workbench/deploy/run-server.cjs#L6)。

8. **P2 · 工作台每次发布保留完整旧目录。** 子进程每秒比较修订号，变化后重建四个工作区的快照和 gzip 产物，切换 current 后保留旧目录。部署约定要求人工清理历史目录，持续编辑会累积重复文件，失败发布也可能留下未切换目录。确认 current 正常后，对发布器管理的目录做有界保留，并合并短时间内的连续更新。共享资产的引用关系需要独立核对。见 [发布代码](../../../tools/workbench/deploy/publish-readonly.cjs#L7) 和 [现有保留约定](../../../tools/workbench/deploy/README.md#L15)。

9. **P2 · 工作台恢复需要数据库和共享资产的一致副本。** SQLite 事务内更新版本、历史和回执。同一请求重试不会重复应用变更。共享资产文件先落地，再提交数据库映射，失败时可能留下未引用文件。公开快照用于展示，恢复编辑能力需要各工作区数据库和共享资产。本仓库文档要求切换前备份，未提供工作台定时备份或恢复演练入口。应先验证成套恢复，再考虑按全工作区引用回收孤立资产。见 [事务与回执](../../../tools/workbench/mcp-sqlite.cjs#L149) 和 [资产写入顺序](../../../tools/workbench/mcp-sqlite.cjs#L78)。

### 建议处理顺序

1. 先降低巡检并发，用生产库副本验证轻量清单和持续上报时的跨页行为。发布前演练回退，上线后验证页面、上传和巡检，再单独启用清理。
2. 为遥测的巡检、报表和上传划出并发余量，过载明确返回 503。验收时同时运行巡检、打开后台并写入测试报告，核对拒绝计数和延迟。
3. 补齐遥测原始归档的容量与恢复方案，再按测量结果优化普通列表和重报表。
4. 为工作台单独安排请求边界、快照保留和数据库连同资产的恢复演练。

## 修复结果

- 遥测按巡检、统计、交互、上传及健康检查分配并发额度。满载返回 503 和重试提示，按固定类别汇总请求与写锁数据。巡检从固定快照逐页读取，旧接口沿用单并发翻页和增量详情。普通列表复用筛选项，对局压缩移到写事务前。
- 安装器校验 Nginx 后再切换采集服务。候选验收期间暂停上传，可回退配置、程序链接、服务、定时器及迁移前的数据库。启动失败数据另存，正式清理按独立流程启用。
- 原始归档按实际文件占用计量。成套备份包含 SQLite、引用文件和哈希清单。旧备份可根据经过校验的压缩包清单重建缺失的原始文件索引。
- 工作台网关按路由限大小并流式转发图片，小型 MCP 请求有独立处理余量。发布器合并短时更新，保留当前和上一份快照。备份命令封存工作区数据库及引用资产，校验修订、历史、回执及文件哈希。
